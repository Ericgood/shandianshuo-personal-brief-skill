# 增量采集、事件去重与反馈校准

首次源头研究、每日推荐和每周质量复盘时，与 [daily.md](daily.md) 一起读。借鉴 AIHOT 的工作分层，仍由本人偏好决定找哪些原作者、读什么和为什么推荐；不把通用新闻分数当个人价值，不要求运行 AIHOT 服务。

## 采集：先入口试读，再按真实覆盖续跑

- 每个频道优先使用公开 RSS/Atom，其次官方公开 JSON、网页更新列表或可读账号。试读时核实提取的是条目而非导航、链接回到原文、日期有依据。正文不足则标记等待补取，不凭标题补写事实；视频说明不是字幕，截断帖不是全文。无可靠发布日期的材料保留待核实，不冒充今天发布。
- 采集成功必须同时确认请求退出/HTTP状态和响应内容；失败残留文件不能当新响应。RSS/Atom要正确解码CDATA与实体，网页列表排除分类、标签、分页和“All Posts”等导航，逐项绑定原文链接及日期。批量标题为空、只抽到导航或解析异常时，保留失败/部分状态并修正提取，不以HTTP200或非空链接数通过验收。
- 官网、官方账号、创始人个人账号分别记来源与访问状态；沿用 [官网与创始人覆盖规则](user-updates.md#官网与创始人渠道覆盖)。静态介绍页用于身份核实，不冒充持续内容列表。付费采集、登录和订阅不是本 Skill 的默认依赖。
- 按用户分、当前需要、历史实际产出与距上次检查时间分配预算。低频来源可以降低检查频率并轮转，不能因一轮无更新永久冷落；失败使用合理退避，遵守 Cache-Control / Retry-After，有 ETag 或 Last-Modified 时条件请求。304 只证明对应资源未变，不证明整个站点无新内容。
- 从上次成功覆盖窗口起保留适量重叠，以稳定内容 ID 去重，接住延迟收录和正文修订。区分发布时间、发现时间、抓取时间、正文版本及推荐时间；旧文第一次被发现仍可有价值，不采用“超过48小时就不能推荐”的限制。
- 每次实际请求留简短回执：run_id、source_id、入口、checked_at、响应/读取范围、观察到的 ID、实际覆盖窗口、是否完整、失败及待续位置。仅保存公开研究所需内容，不记凭据或原始模型载荷。成功抓取的公开材料和判断可在同版本重试时复用，旧缓存明确标旧缓存；规则或正文变化后重新判断，不能当作今天重新抓取。
- 分页中断、登录受限、只看到部分帖文时，保存已取得条目、最后观察时间和本轮断点，**不推进“完整覆盖成功”游标**。只有窗口完整检查且条目/回执保存成功才推进相应频道成功游标；动态列表本身不保证完整时持续标部分覆盖。失败不写“无更新”。断点过期则重新从可用入口读取并按 ID 接续，不伪造下一页。
- 前N条和单页读取默认只表示该范围；要标完整目标窗口，需保存旧成功边界、当前边界和已达列表末尾/覆盖旧边界的证据，不能把截取上限当结束。静态页面核实成功与动态内容窗口成功分别记录。验收时实际抽查提取条目和窗口证据，不能只检查自己填的complete=true。

来源现有字段可继续沿用，在运行回执补充 coverage_window、complete、resume、cache/revision 等必要字段；不为统一格式覆盖旧账或硬迁移。记录实际已查频道、条目数、正文阅读数、缓存复用数和缺口，不能把三个频道的各五条样本写成三份完整时间线。

## 去重：原文、内容版本、事件和用户曝光分开

先使用现有 URL / 平台原生 ID 归一。明显相同原文共享内容身份，保留各出处与版本；正文指纹只辅助发现转载，不用整页 HTML 哈希当正文相同的证明。作者跨平台关联与内容合并是不同动作，不能凭同名合并人，也不能把一个人的所有帖子合成一条。

对有入选可能的内容提取可核实的“主体、动作/主张、对象、事件时间和出处”，与候选及已有事件比较。判断以下关系并保存比较对象和证据：

| 关系 | 处理 |
|---|---|
| 同原文 / 同版本 / 转载复述 | 合并出处；沿用既有研究和曝光，不产生新推荐 |
| 同事件且没有新增信息 | 并入事件背景，不另占日报名额 |
| 同事件但有实质进展、独立实测或反证 | 说明与旧内容相比新增的具体事实/方法/结论；按30天规则决定是否补充 |
| 主题相近但回答不同问题 | 保留独立候选，再检查整份日报的互补性 |
| 证据不足 | 保留待核，不强行合并或声称独立增量 |

转载和引用链不算多个独立证据。代表原文按本条要回答的问题选择：确认产品功能优先可核实的一手资料，了解经验和批评可选创始人、用户实测或独立作者；官方身份不自动获得更高个人价值。保留互补出处，不能用一个代表链接遮住相反证据。

候选判断先记录“个人价值及证据”，再单独记录“相对已有内容的增量”和最终编排理由。对可能入选但关系不明的高价值冲突项，可在最终编排前单独复核原文事实与重复判断；不强制每篇都打两次分，也不把模型重复判断当独立事实核验。继续执行 [30天避重与重荐例外](daily.md#跨日重复与有理由的重荐)，不以新标题、新作者或过窗口绕过曝光历史。

## 校准：用真实用户反馈检查筛选，而非制造标签

在实际状态目录维护 `feedback.jsonl`，原子保存并以稳定 feedback_id 幂等追加。已有等价反馈账则沿用。每项保留 observed_at、用户原话的必要短摘/可信会话定位、target_type（item/report/source/topic/policy）、target_id 或明确未知、context、用户明确判断和实际生效规则；模型解释另列且标候选。私人反馈留本机，不进入公开仓库或搜索查询。

- 只有用户明确评价了某条，才为该条记录 select / reject / either（愿意看 / 不想看 / 两可）；未评价维持 unknown。模型自评不能充当用户金标。
- 区分不感兴趣、重复、暂时不需要、内容不可靠、形式不合适。因重复没入选的好文章不等于个人价值低；因今天名额未选也不等于 reject。缺失或未点击都不是负反馈。
- 整份日报的“质量不错”保留为 report 反馈，不能拆成每条 select；“近期语音太集中”作用于编排，不把语音主题永久降分；“旧文很好”不表示所有旧文都值得推荐。
- 明确偏好与纠正当轮生效，关联来源/主题及规则版本，保留旧记录；来源用户分和本人确认状态不可被自动覆盖。只有模型推测的调整先列建议，不擅自改稳定偏好或制造用户评分。

日常不强迫用户逐条打分。将新候选的选择理由与已明确反馈比较，记录实际冲突和所用规则；没有条目级反馈时写“尚无可计算的条目级校准”，仍可验证明确的编排要求。

每7天质量复盘（接入现有每周复盘，不另建任务）检查自上次成功复盘后的真实反馈、候选及最终选择：

1. 分开看个人价值判断、重复判断、组合多样性和阅读/抓取覆盖。列出已确认的误选、漏选及原因；不知道的保留未知。
2. 有足够明确标注时，用同一批样本比较旧规则和拟议规则；调规则使用开发样本，另留未参与调节的样本验收。样本少先看具体错例，不用几个好评宣称准确率提升，也不强行补齐标签。
3. 只有存在真实分母时才报指标，同时注明已评价/全部推荐数、未评价数、模型失败与未知判断；抽取不完整时说明范围。样本中的选择准确率不代表全网召回率。没有反例/完整候选就不报查全率。
4. 将变更理由、真实反馈 ID、规则版本（可用本次相关指令文件哈希）及拟议影响写入复盘。验证通过再应用候选规则；用户明确指令立即应用。变更只影响后续判断，不改写旧推荐回执，不把更换规则说成旧样本已重评。

## 每轮交付与验收

除日报外，在本轮审计保留来源请求回执、候选及事件增量判断、反馈账/校准记录和实际用的规则版本；包含合并/跳过的真实例子，无例子则明确本轮未遇到。资料库日报附简短覆盖与去重说明，详细审计留 outputs，避免技术日志淹没阅读正文。确认两处正文、资料库索引保存成功后才写推荐曝光。

复用既有授权、状态和成功基线，不重新读取全年原始文字，不新增付费接口或部署服务。实跑预算不足可缩小轮询范围并明示，不宣称所有来源已检查；没有值得推荐的新增内容可交付零条覆盖报告，不拿已推荐内容凑实测结果。
