# 首次访谈与首份结果

目标不是让人先填长表，而是用几个必要问题建立分析范围、身份和当前需要，完整理解后马上给今天的内容。首次启动先做本页；恢复已有分析时使用已经确认的答案，不重新采访。

## 访谈顺序

优先用宿主当前公布的问答/选择工具，参数以真实schema为准；没有就用对话。一次只围绕一个问题，已有明确答案就沿用。不要虚构固定的DeepSeek Harness提问工具名。

1. **分析多长时间？** 未指定时问“想分析最近30天、90天、过去一年，还是指定一段日期？”解释：窗口越长、记录越多，一般分析越久、模型消耗越大，能看到更多变化，但不保证越长越准确。选定范围后用inventory给实际记录/批次数与缺失时段，不凭空承诺分钟数或金额。最长365天；实际不足则说明。
2. **你现在是谁、在做什么？** 先读已有USER.md及本任务明确资料。存在可用背景时只概括主要角色/领域/当前工作，问“资料里写你主要是……，现在仍然准确吗？有变化可以补充。”没有可用背景时问“你主要做什么，最近在忙什么？工作和个人角色都可以说。”不要求真实姓名、雇主或联系方式；允许跳过。刚刚当轮本人已明确提供或确认的身份视为已回答，不机械重问。只从旧转写推断的身份不得用肯定语气冒充自填。
3. **目前最希望了解什么？** 问最近最想解决/了解的事，以及不想看哪些内容。回答用于提高当前相关性，不替代后面全量理解，也不删除尚未在访谈中提到的生活/创作等兴趣。用户可说暂时没有，让Agent根据全量历史提出候选。
4. **私人文字交给哪个模型？** 仅在没有明确授权时，说明将由当前助理实际选择的模型服务处理，按宿主要求确认接收方；已明确授权就不重问。不承诺纯本机，不默换其他供应商，不读取API key。
5. **报告按哪个时区？** 优先采用用户已明确或宿主可靠提供的IANA时区，不凭语言、IP或旧资料猜测；无法确定时，在给首份报告确定“今天”的日期之前询问。后续定时沿用该时区，只补问尚未确定的每日运行时间，不把首次报告日期的确定拖到日程设置阶段。

把范围、已确认/可靠获知的时区、身份确认/跳过状态、当前需要、明确负偏好与授权状态保存到本任务settings.json，例如：

```json
{
  "onboarding": {
    "reference_days": 90,
    "identity_status": "confirmed",
    "identity_summary": "仅填写用户实际确认的主要角色与领域",
    "identity_source": "USER.md + 本轮确认",
    "identity_confirmed_at": "真实时间",
    "current_needs": [],
    "negative_preferences": [],
    "model_processing_authorized": true
  }
}
```

这是字段示例，不是可直接采用的用户事实。与settings既有范围字段同步，不覆盖其他设置；缺身份时identity_status=skipped/unknown，summary为空。用户更正只存本任务文档，不擅自回写USER.md。身份没有回答不应该阻塞其明确授权的转写分析。

## 分析完成后的两个成果

先完成全部语义阅读和归纳审计，形成原生资料库文档library/个人信息偏好.md。身份、本人确认的当前需要与全文理解共同解释偏好；访谈的几个答案不能冒充历史阅读，也不能只按职业筛内容。

**接着立即做今天的源头研究和推荐**，不是等待下一次日程触发。保存reports/YYYY-MM-DD.md审计版本，同时将完整正文保存到原生资料库library/每日信息推荐-YYYY-MM-DD.md并更新可点击索引，回读验证后才交付；日期取实际完成时的用户时区；分析跨日也不能把完成日新闻写成开始日新闻。每条给原作者身份、真实原日期/链接、内容、对应偏好、为何今天值得看、阅读限制。

正常首轮交付应让用户看得到两个链接，并在对话中给出当日推荐要点。输出0—10条，允许真实零条报告；无数据时冷启动标明，未完成分析/访问失败时标明缺口，不能伪造“今天感兴趣的新闻”。先保存报告再记推荐账。

## 然后才安排每日运行

当日首版已展示后，若用户还没要求每日任务，询问是否每天继续；已要求但缺具体设置，只问“每天几点、哪个时区？”沿用明确选择，不把北京时间或9点作为所有人的默认答案。已有同目的任务先查重。

用真实调度工具创建或更新并回查；缺能力就保存任务模板并明确指出。首次结果不依赖scheduler可用，不能因没有定时插件就跳过本轮推荐。邀请用户纠正身份、推荐或信息偏好即可，不强制其打完所有分才继续已授权工作。
