# 用户主动添加信源与偏好

用户可直接说“关注某作者/账号”“以后多看某主题”“今天想找某内容”“少推这个”“取消关注”。已有档案时进入本流程，不重做首次访谈、不等待每日/每周任务；尚未建档也可先保存明确要求，不能冒称已理解历史。

## 先理解这次要求

- **作者/账号/URL**：记为用户指定信源，核实真实身份、平台入口与公开内容。关注作者不等于认可所有观点，也不推断用户从事该行业。
- **产品/公司/项目**：保存为明确关注对象，分别寻找官方更新、创始人/一线作者、独立实测等关联信源；产品名本身不是发布者。官网静态介绍或法律页面可核实身份，不能冒充持续内容供给；无更新入口则记录缺口，继续按主题补原作者。第三方来源仍是Agent发现候选，不能自动算作用户亲自指定关注。
- **持续主题与内容口味**：“以后多推”“我一直关注”记为用户明确偏好，立即影响搜索和排序，不等每周复盘。
- **临时需要**：“今天想看”“最近在做”记到有日期的近期需要；仅说“想看X”而未表达持续关注时，先记本次要求、持续性未知，不自动升为稳定人格。
- **负反馈/取消**：记录适用范围与日期，停止相应主动推荐/轮询，保留历史及理由；取消某作者不等于不喜欢整个主题。

同名或账号归属会影响结果时先查公开证据，仍无法消歧才问一个简短问题；保存待核实项并继续不依赖它的工作。已明确的目标和变更不重复确认。用户说“关注”仅授权本任务本地信源登记，不自动在平台关注、注册newsletter、购买订阅或对外发布。

## 当轮搜索并双向关联

先读完整现有profile、sources与相关反馈，保留已有手动编辑。先将明确要求安全保存为待研究，随后当轮以必要的公开主题词/作者名/公开URL搜索，从原站About、署名、账号链接及近期原文确认身份与内容方向。搜索请求不带私人转写、身份档案或无关关系细节。没有联网工具或访问失败时保存pending和原因，不能说已研究/已启用检查。

指定信源时读可取得的更新列表及至少一篇有代表性的原文，注明实际读取范围与日期；只见列表/摘要/付费预览就保留局限。指定主题时寻找适合的原作者/机构，优先核实少量优质入口，不将搜索结果全自动变成“用户关注”。核实前为candidate；核实后可登记为Agent发现来源，linked_preferences指向本人要求，仍区别于用户亲自指定的follow。不能把主题当作者或名字提及当发布者，不凭同名硬合并。

复用稳定来源ID；已有Agent候选被用户点名关注时，必须把当前关注状态转为follow/active并记下本人要求，不能只追加历史而仍留在candidate。保留最初发现归属，另记当前用户关注及日期。取消后再次明确关注则恢复当前关注，历史仍保留。同一作者多平台保留身份关联，机构不同频道不随意合并。sources中保留实际字段（可按现有schema命名）：用户指定/Agent发现、requested_at、follow_status或candidate状态、原始入口、身份/背景证据URL、核心内容、linked_preferences、最近实际检查/失败。明确关注可优先分配检查预算，但user_score保持原值或null，只有本人明确给分才写用户分；模型暂定分另存，样本不足不装作已证明质量。添加来源的时间不是抓取成功游标。

profile在原生资料库的“本人明确要求/近期需要/负反馈”等适当位置记录主题、持续/临时/未知、日期、确认来源和关联来源ID；新来源推导出的兴趣仅作候选，不倒过来替用户确认。明确更正即时生效；只有稳定层系统复盘完成才推进stable_reviewed_at。取消或替换保留历史记录，不删除过去推荐。

## 保存、可见与测试

先读后改、避免与每日运行并发；有运行时将要求记待合并，接续同一run，不能两个Agent同时覆盖profile/sources。原子保存，回读核对profile和来源关联，再更新library/每日信息推荐.md的关注入口摘要/链接，让用户能在资料库找回。只维护一份来源权威JSON，不另造易漂移的来源清单；用户可直接让助理查询、加减和修正。

简短回报“已记录的偏好/信源、身份依据、实际读到什么、何时参与推荐及尚待核实什么”。保存与研究是不同状态；不能说关注已登记就承诺每天必有内容。添加要求不自动把样本算作推荐；用户明确还要现在看推荐时，完成原文研究并沿用去重与交付规则。

原生验收用临时合成档案测试主题与作者的区分、长期/临时、同名待核实、重复添加幂等、取消保留历史、用户分数不被模型覆盖；再以一个明确标为测试、不自动关注的公开主题实际搜索核实原作者并回读产物。不得把测试主题写入真实用户偏好或真来源账。
