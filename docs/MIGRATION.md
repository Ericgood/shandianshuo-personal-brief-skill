# 换电脑与接续运行

更新时间：2026-10-28。这个仓库只保存通用 Skill；克隆仓库不会恢复某位用户的偏好、理解进度、来源和推荐历史。

## 需要分别迁移的东西

| 材料 | 迁移方式 | 验证 |
| --- | --- | --- |
| 通用 Skill、脚本、模板与文档 | 克隆本仓库，记录分支和提交 | 核对远端提交，检查完整文件集合 |
| 已安装 Skill 的本机兼容补充 | 随原生工作区私下迁移，另存旧版 | 比较安装副本与仓库；不能用仓库直接覆盖本机补充 |
| 闪电说原生工作区 | 使用私有备份或应用受支持的迁移方式 | 回读资料库、原始历史与分析覆盖审计 |
| 定时任务 | 在实际调度宿主核查、恢复和验收 | 核对任务 ID、时间、时区和实际完成记录，避免双重执行 |
| 账号、密钥、签名与登录态 | 使用系统迁移或原服务受支持的安全方式 | 新机重新核验；不提交到 GitHub |

迁移前记录真实工作区路径。常见 macOS 国内版工作区是 `~/Library/Application Support/Shandianshuo/workspace/`，实际位置仍以宿主为准。

工作区需要保留整个关联文件集合，而不只复制一份偏好文档：

- `library/`：权威偏好、完整日报、可点击索引、安装的完整 Skill。
- `history/`：原始转写；只迁移，不删除或改写记录。
- `outputs/`：年度与增量分析证据、冻结输入、覆盖账、成功基线及元数据、来源/内容/反馈账、运行审计和报告。
- 工作区自身规则及其他依赖：在本机确认实际路径；模型配置可能涉及凭据，使用安全迁移方式。

早期实例使用 `outputs/personal-daily-brief/daily-monitor/`，通用 helper 默认使用 `outputs/personal-brief/`。先读取已有 settings 和安装副本的兼容段，沿用真实状态，不能另建空账或把旧状态直接当作新版 helper manifest。

## 备份与恢复顺序

1. 先确认原生助理是否正在执行任务；已有运行先保留断点，不启动并发写账者。应用数据库若在写入，使用其受支持的一致性备份或系统迁移；热拷贝不算已验证恢复。
2. 盘点本地分支、未提交文件、独有提交、worktree 和被 Git 忽略但无法重建的资料。代码与私有资料分开备份；不把凭据、个人画像、原始文字和分析笔记上传公开仓库。
3. 私有备份保存文件清单、字节数、哈希与读取失败；备份后从目标位置回读验证。云盘占位或只存在文件名不算可恢复副本。原始材料和历史备份保留。
4. 新机克隆代码，恢复私有工作区和完整 Skill；检查符号链接实际目标、权限和全部依赖。按本机规则保留本地运行副本，不重新指回旧电脑、云盘占位或离线磁盘。
5. 若用户名或工作区路径变化，先核对 settings 与兼容脚本中的绝对路径。不要全局替换私人数据正文，不重跑封存的首次基线构建器。
6. 原生助理自行读取已安装 Skill、完整偏好、最新反馈及成功指针，核对完整 SHA、元数据和验收账。按 occurrence/指纹处理所有漏跑增量，不仅是最近两天或七天。
7. 完成已到期的稳定偏好复盘，保留用户评分和明确拒绝；近期需要每日更新。失败不推进任何成功状态。
8. 原生助理实际独立选题、读取原文、写资料库日报及索引，回读后才记曝光。外部 Agent 的文档、脚本测试和文件复制不等于原生运行成功。
9. 最后验证定时触发。原调度和新调度不能并发写账；迁移到新调度前先验收新任务，再停止旧任务。新机没有电脑操作/宿主派发能力时，要记录“未派发”，不能生成替代日报冒充通过。

## 恢复验收清单

- 已安装、已启用、已加载、分析完成、日报保存、通知送达分别有证据。
- 年度分析和已验收增量都仍可追溯，未理解部分保持待读；不重新默认读取全年。
- 所有历史推荐继续保留，原文与语义去重按近30天规则执行；旧文首次推荐允许。
- 资料库可直接打开完整日报，索引链接有效，审计版本与运行 ID 对应。
- 来源实际读取范围、失败、分页断点与成功游标一致；旧缓存不冒充今天抓取。
- 新机实际原生运行成功与跨日调度成功分开验收；缺失能力和未验证项明确列出。

这份文档没有包含任何用户私有状态。具体实例的最后成功日期、基线哈希、待补证据和迁移备份位置，应写进该实例的私有交接文档。
